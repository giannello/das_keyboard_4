## Liberating Das Keyboard 4

Das Keyboard 4 is a mechanical keyboard launched in 2014 by Metadot.
It features a 104-key layout with Cherry MX switches, media keys, a rotary encoder and a sleep button.

## Hardware information

The keyboard is built around a Nuvoton [NUC123](https://www.nuvoton.com.cn/export/resource-files/DS_NUC123_Series_EN_Rev2.05.pdf) microcontroller, mounted on a dedicated circuit board housing a VIA USB hub.
The circuit board is loosely packed with components, and it conveniently contains test points for SWD programming and debugging using OpenOCD.

## Firmware

The microcontroller runs a proprietary firmware, made of a bootloader and a main application. They are independently updatable using a dedicated update tool available for Windows and macOS.

Firmware update packages are usuall distributed as ZIP archives containing one (or more) firmware files, and an executable that interfaces with the microcontroller on the keyboard using a custom protocol over USB-HID.

Both the bootloader and the main application have a integrity checks in place.
When plugging in the keyboard, the bootloader will verify the checksum of the main application, and will not start the main application if the checksum does not match.
When the main application is running, and it tries to reboot in bootloader mode, it will verify the checksum of the bootloader, and will not reboot if the checksum does not match.
This prevents the keyboard from entering an invalid state, and is a security measure to prevent the keyboard from being bricked.

The firmware and update tool are developed by [Heng Yu Technology](https://www.hengyu-tech.com/)

### Das Keyboard 4 Professional/Ultimate

The latest published firmware is available [here](https://download.daskeyboard.com/firmware-releases/DK4PRO/USB_FD2_PC.zip). The package contains:

* The main application binary (L1947V33.bin)

## Firmware update process

Both the bootloader and the main application can be used for firmware updates, as they implement an ISP mechanism. Given that a running application can _not_ update itself, the main application is used to update the bootloader, and the bootloader is used to update the main application.

The update tool detects the type of file to be flashed, and can reboot the keyboard into bootloader mode if necessary.

Based on the analysis of the update tool, the update process takes the following steps:
1. erase the target memory region
2. pass the firmware to the microcontroller
3. protect the target memory region
4. reboot the microcontroller

The update tool also implements a basic file integrity check, by verifying the content of a specific location of the firmware file with the string `{j`. This string seems random, but it will be more clear once we delve into the details of the firmware files.

## Firmware details

The flash area of the microcontroller is read-protected, and is not accessible using SWD. Extracting the firmware is not possible without overwriting the flash with custom code that implements ISP and is therefore able to read the protected memory regions.

To under    stand the obfuscation strategy, we need to start with some known values.

First of all, we can see that most of the code is padded with or contains `0xff`, which is unusual. Also, the files don't seem to have a very high entropy, so we can assume that there is no encryption going on, but only some basic obfuscation.

This `0xff` instead of `0x00` is a hint at a potential bit inversion. Let's try to invert the bits and see if we get something meaningful:

```python
import sys
import os

def invert_bits(input_path, output_path):
    """
    Reads a file and flips every bit (0 -> 1, 1 -> 0).
    Works on any file size by processing in chunks.
    """
    if not os.path.isfile(input_path):
        print(f"Error: {input_path} not found.")
        return

    try:
        with open(input_path, 'rb') as infile, open(output_path, 'wb') as outfile:
            print(f"Flipping bits: {input_path} -> {output_path}")

            # Process in 4KB chunks for memory efficiency
            while True:
                byte_chunk = infile.read(4096)
                if not byte_chunk:
                    break

                inverted = bytearray()
                for byte in byte_chunk:
                    # ^ 0xFF flips all 8 bits in a byte
                    a = byte ^ 0xFF
                    inverted.append(a)

                outfile.write(inverted)

        print("Operation complete. All bits have been inverted.")

    except Exception as e:
        print(f"An error occurred: {e}")

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print("Usage: python invert_bits.py <input_file> <output_file>")
    else:
        invert_bits(sys.argv[1], sys.argv[2])
```

Looking at the bit inverted files, we can immediately see a familiar "2" in the first bytes, but in the wrong position. Could it be that the obfuscation at this point is a simple nibble inversion? Let's see:

```python
import sys
import os

def swap_nibbles(input_path, output_path):
    """
    Reads a file and swaps every nibble (00001111 -> 11110000).
    Works on any file size by processing in chunks.
    """
    if not os.path.isfile(input_path):
        print(f"Error: {input_path} not found.")
        return

    try:
        with open(input_path, 'rb') as infile, open(output_path, 'wb') as outfile:
            print(f"Swapping nibbles: {input_path} -> {output_path}")

            # Process in 4KB chunks for memory efficiency
            while True:
                byte_chunk = infile.read(4096)
                if not byte_chunk:
                    break

                # Use a bytearray for fast manipulation
                swapped = bytearray()
                for byte in byte_chunk:
                    # bitshift, pad, and combine
                    a = ((byte << 4) & 0xF0) | ((byte >> 4) & 0x0F)
                    swapped.append(a)

                outfile.write(swapped)

        print("Operation complete. All nibbles have been swapped.")

    except Exception as e:
        print(f"An error occurred: {e}")

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print("Usage: python nibble_swap.py <input_file> <output_file>")
    else:
        swap_nibbles(sys.argv[1], sys.argv[2])
```

First of all, let's figure out a checksum algorithm. Let's try with a simple sum + 2-complement.

```python
import struct
import sys

def calculate_checksum(file_path):
    with open(file_path, 'rb') as f:
        data = f.read()

    # Exclude the last 4 bytes (the checksum field)
    body = data[:-4]

    # Ensure the data is 4-byte aligned
    if len(body) % 4 != 0:
        print("Warning: Data is not 32-bit aligned.")

    # Unpack data as Little-Endian 32-bit words
    words = struct.unpack('<' + 'I' * (len(body) // 4), body)

    # Calculate the sum (truncated to 32 bits)
    total_sum = sum(words) & 0xFFFFFFFF

    # Calculate Two's Complement
    checksum = (0 - total_sum) & 0xFFFFFFFF

    return checksum

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print("Usage: python checksum.py <input_file>")
    else:
        result = calculate_checksum(sys.argv[1])
        print(f"Calculated Checksum: {hex(result)}")
```
